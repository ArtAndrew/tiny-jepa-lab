# Разработка ORBIT

Нужны Python 3 и Node.js 24. Сторонние Python- и npm-пакеты для сайта и рейтинга не требуются.

```sh
python3 scripts/build_site.py
node --test scripts/test_*.cjs
python3 -m http.server 8000 --directory docs
```

Откройте `http://localhost:8000/ru/`. Обычная локальная сборка создаёт пустой снимок общего рейтинга. Для получения актуальных результатов:

```sh
node scripts/build_leaderboard.cjs
python3 scripts/build_site.py --leaderboard docs/assets/leaderboard.json
```

API GitHub используется только сборщиком. В Actions он получает временный `GITHUB_TOKEN` с правами чтения. В браузер токен не попадает; браузер читает готовый JSON с того же сайта.

## Публикация и рейтинг

`.github/workflows/pages.yml` запускается при push в `main`, изменении заявок и вручную. Сборка проверяет повторы, собирает страницы и публикует их через GitHub Pages. В Settings → Pages выбран источник **GitHub Actions**. Основание конфигурации: [официальная документация Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) и [события Issues](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#issues).

- Принимаются открытые Issues с маркером `<!-- ORBIT_REPLAY -->` и JSON из кнопки отправки.
- Схема содержит только версию правил, модель, день и пять троек действий −1 / 0 / 1. Число очков, координаты и имя игрока от клиента не принимаются.
- Аккаунт берётся из данных GitHub. Дата — не будущая и не старше 30 дней UTC. Заявка должна быть создана не раньше игрового дня.
- Очки пересчитываются теми же функциями физики, которые работают в браузере. В каждой паре «аккаунт + день» остаётся лучший результат; при равенстве — более ранний номер заявки.
- Закрытые заявки, Pull Requests, аккаунты типа Bot и заявки с меткой `orbit-exclude` не включаются. Обычный аккаунт тоже может использовать автоматизацию: проверка этого не обещается.
- Метка `orbit-test` запускает проверку, но не добавляет тестовый счёт в таблицу. Результат проверки виден в сводке запуска Actions.
- Ошибка или неполная загрузка GitHub API останавливает публикацию: рабочий сайт остаётся доступен с предыдущей таблицей.

Сборка и проверка имеют только права чтения. Права `pages:write` и `id-token:write` выданы отдельной задаче публикации. Текст заявок читается как JSON и не выполняется как код или shell-команда. Все Actions закреплены на commit SHA.

## Файлы проекта

- `source/ORBIT_JEPA_RU_EN_ZH.html` — неизменённый автономный исходник с обученными весами.
- `source/introduction.*`, `source/explainer.*`, `source/theme.*`, `source/controls.css`, `source/leaderboard*` — изменения интерфейса и переводы.
- `scripts/build_site.py` — сборка трёх языковых страниц и извлечение общих правил в `game/`.
- `game/engine.js`, `game/orbit.js` — код из исходного HTML, общий для браузера и проверки очков; вручную не редактировать.
- `scripts/leaderboard.cjs`, `scripts/build_leaderboard.cjs` — валидация повторов, пересчёт и загрузка заявок.
- `docs/` — статические страницы. При публикации в них встраивается актуальная таблица; `docs/assets/leaderboard.json` используется для обновления без перезагрузки игры.

## Учебные материалы

[Notebook](materials/ORBIT_Action_Planning.ipynb) теперь выполняется из текущего репозитория: NumPy-загрузчик и симулятор находятся в `planning/`, отдельные веса — в `artifacts/action_jepa/`. Семь ячеек проверяются автоматически. Исходный notebook перенесён в [архив](materials/archive/ORBIT_Action_Planning_v03.ipynb).

[Как воспроизвести обучение и проверку](REPRODUCIBILITY.md) · [Архитектура](MODEL_CARD.md) · [Новые результаты](BENCHMARK.md).

Новый рецепт обучения предиктора реализован в `planning/training.py`; конфигурация — `configs/train-actions.json`, три измеренных прогона — `experiments/`. Для полного обучения с нуля в v0.5 добавлен `planning/original_training.py`: он проверяет хеши исходников, запускает восстановленный код из `ml/original-training/` в пустом временном каталоге и экспортирует полный комплект весов. [Рецепт и результаты](FROM_SCRATCH.md). Модель и правила дневного рейтинга сохранены.

`reports/benchmark.json` содержит новые измерения; `scripts/build_research_docs.py` формирует таблицы из этого JSON. Сайт показывает результат опубликованной модели на 3 072 новых сценах. Исторический [отчёт](materials/ORBIT_RELEASE_REPORT_RU.md) сохранён отдельно и не подменяет новые измерения.

`source/failures.*` и `scripts/build_failures.cjs` создают три воспроизводимых примера промахов. Они открываются только в лаборатории и не добавляют очки дневного рейтинга. `source/navigation*.js` переключает реальные языковые адреса без потери состояния; адреса изображений и запросов закрепляются до изменения пути.

Workflow `research.yml` выполняет независимую проверку Python/JavaScript, короткое повторное обучение и оба notebook. Он использует только права чтения и не публикует новые веса автоматически.

## Материалы для публикации

`scripts/export_demo.cjs` пересчитывает выбранный пример по исходным правилам и встроенным обученным весам. `scripts/build_media.py` рисует иллюстрированный повтор, GIF, MP4 и обложки; это не запись экрана. Для генерации медиа отдельно нужны Pillow и imageio-ffmpeg. Готовые файлы включены в репозиторий, обычная сборка сайта этих зависимостей не требует. Пути шрифтов можно переопределить через `ORBIT_MEDIA_FONT`, `ORBIT_MEDIA_BOLD` и `ORBIT_MEDIA_CJK`.

```sh
node scripts/export_demo.cjs
python3 scripts/build_media.py
python3 scripts/build_site.py
```

Основной README — на английском; русская и китайская версии находятся рядом. `promotion/` содержит анонсы, описание релиза и черновик статьи. Публикация этих текстов во внешние сообщества выполняется отдельно.
