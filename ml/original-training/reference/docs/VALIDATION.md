# Отчёт проверки Tiny JEPA Lab

## Что было выполнено

Две модели действительно обучены с нуля на CPU по 2 400 шагов с batch size 128,
одинаковым seed 42 и одинаковыми синтетическими входами. Обычная модель использует
веса variance/covariance 10/1; контрольная — 0/0. Инициализация одинаковая.

Для каждой модели после заморозки JEPA отдельно обучен координатный readout:
8 192 наблюдаемых кадра, 800 шагов, seed данных 10001. Readout не обучался
на предсказанных эмбеддингах. Итоговый тест — 2 048 новых траекторий на режим:
обычный seed 20001, высокий шум 20002, двойная скорость 20003.

## Результаты основной модели

На обычном тесте средняя координатная ошибка JEPA + readout — **0.8233 px**,
приближённый 95% интервал по тестовым примерам: **[0.7979; 0.8487] px**.
Stationary baseline: **3.4117 px**; baseline с явно заданным законом отражения:
**0.2596 px**. Ошибка readout на наблюдаемом кадре: **0.2301 px**.

Latent MSE: **0.05267**; сохранение представления последнего кадра: **0.75871**;
сопоставление с перемешанными будущими кадрами: **2.18961**. Поиск правильного
будущего среди 64 случайных кандидатов: **78.61%**; случайный выбор: **1.5625%**.
Среднее std признаков: **1.0505**, эффективный ранг ковариации: **6.674 / 8**.

При шуме 0.18 вместо 0.03 ошибка JEPA — **4.7320 px**, а stationary baseline
лучше неё. При удвоенной скорости ошибка JEPA — **3.0044 px**. Точные значения
сохранены в JSON и имеют приоритет над округлёнными числами в тексте.

## Контроль без регуляризации

Latent MSE ≈ **2.44e-7**, среднее std признаков ≈ **0.000598**, но ошибка
JEPA + readout — **5.983 px**. Это наглядный случай почти схлопнувшихся
представлений. Сырые MSE разных моделей несопоставимы без учёта масштаба.

## Проверки исполнения

Пройдены **16 автоматических тестов**: генератор и его воспроизводимость;
разные seeds; формы и диапазоны; отражение; размер выходов; отсутствие будущего
кадра и координат во входах предиктора; отсутствие градиентов учителя;
правильность EMA; штраф константных признаков; шаг оптимизатора; сохранение
и загрузка NPZ; некорректные входы; число параметров; эквивалентность
экспортированного JavaScript-инференса и PyTorch на восьми новых примерах.
Допуск последнего теста — 2e-5 по абсолютному и относительному отклонению.
Лог — `tests.log`.

Отдельно проверены CLI-обучение с нуля, продолжение checkpoint, evaluation
и экспорт новых весов. Четыре непрерывных шага и запуск «2 шага + resume до 4»
дали полностью одинаковые веса, побитно на всех массивах.

Выполнен весь notebook: **13 ячеек**, включая просмотр кадров, inference,
короткий учебный цикл обучения и анализ основной/контрольной моделей.

Самодостаточный HTML загружен в Chromium через Playwright `set_content`.
Проверены обычная модель, контрольная модель, высокий шум, воспроизведение
движения и мобильная ширина 390 px. JavaScript-ошибок не обнаружено,
горизонтального переполнения на этой ширине нет. Веса и вычисления локальны;
внешние ресурсы для работы интерфейса не запрашиваются. Снимки интерфейса —
`demo_preview.png` и `demo_mobile.png`.

## Среда и границы проверки

Python 3.13.5; PyTorch 2.10.0+cpu; NumPy 2.3.5; Linux; два CPU-потока.
Для проверки экспорта использовался Node.js 22.16.0. GPU-ветки CUDA/MPS
предусмотрены, но не выполнялись. Safari, Firefox и Windows в этой среде
не проверялись. JavaScript не требует внешних библиотек.

Это демонстрация с одной основной инициализацией, а не сравнительное
исследование многих JEPA-методов. Интервалы не учитывают разброс по обучающим
seeds. Полной инвариантности к шуму нет. Известная физическая формула здесь
лучше сети. Действия, планирование и реальное видео не реализованы.
