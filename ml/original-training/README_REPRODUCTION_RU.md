# ORBIT / Tiny JEPA Lab — исходный метод, восстановленный из оригинального архива

Этот пакет содержит **исходный код оригинального обучения** энкодера v0.1 и предиктора действий v0.3. Файлы `tinyjepa/core.py`, `train.py`, `tinyjepa/evaluation.py`, `evaluate.py`, `planning/model.py`, `train_actions.py` и `evaluate_actions.py` скопированы без алгоритмических изменений из сохранённых архивов. **Готовых весов в этом пакете нет** — они предлагаются отдельным архивом. `reference/` содержит оригинальные JSON-результаты и логи, а не действующие checkpoint.

## Быстрый запуск с нуля

Понадобятся Python 3.13.5, CPU, Node.js (для точного тестового протокола JavaScript), желательно PyTorch 2.10.0+cpu и NumPy 2.3.5. Смотрите `requirements-original.txt` для версий исходного успешного запуска и `requirements-compatible.txt` для более гибкой установки.

```bash
python -m venv .venv
source .venv/bin/activate   # для Windows: .venv\Scripts\activate
python -m pip install -r requirements-original.txt
bash scripts/reproduce_all.sh
```

Опциональный контроль схлопывания (ещё 2400 шагов + probe):

```bash
WITH_ABLATION=1 bash scripts/reproduce_all.sh  # только для ЧИСТОГО каталога
```

Для отдельного запуска контроля после основного опыта:

```bash
python train.py --out artifacts/no_regularization --steps 2400 --batch-size 128 --seed 42 --threads 2 --device cpu --lr 0.001 --variance-weight 0 --covariance-weight 0
python evaluate.py --model artifacts/no_regularization --samples 2048 --probe-steps 800
```

### Учтите

- Первая стадия учится **динамическому предсказанию будущего**, не двум аугментациям одного кадра. Два кадра `t0,t1` + one-hot горизонт `h=1..4` → `z_future`. В teacher подаётся настоящий `t1+h`, его параметры обновляются EMA, а не градиентом.
- Формула loss: `10 * mean((prediction - stopgrad(EMA_teacher(future)))**2) + 10 * mean(relu(1 - sqrt(var_biased(z)+1e-4))) + 1 * sum(offdiag(cov_unbiased(z))**2)/8`.
- **Точная особенность исходника:** штрафы variance/covariance вычисляются на конкатенации `[encoder(t0), encoder(t1), encoder(future)]` (3B наблюдений); `future` одновременно проходит в online-энкодер *для регуляризации*, но не во вход предиктора. Это легко пропустить при повторной реализации.
- Ни координаты, ни скорость, ни функция отражения не передаются в JEPA-loss. Генератор используется для создания кадров и диагностических меток.
- Обновление EMA: teacher ← 0.99·teacher + 0.01·encoder **после каждого шага**.
- Основной checkpoint — **последний, шаг 2400**; никакой отбора по validation loss на первой стадии. Регулярные сохранения каждые 200 шагов, только последнее состояние остаётся в `model.npz`.
- Probe: замороженный `model.teacher`, 8192 будущих изображений с seed 10001, MLP 8→64→64→2 и `sigmoid`, Adam lr .003, batch 256, 800 шагов, метки координат только здесь.
- Action: замороженный **EMA teacher** из первой стадии (не online `encoder`!), 65536 синтетических траекторий и 2048 validation, 5000 шагов, batch 256, AdamW .001, weight decay 1e-4, cosine decay до .0001. Выбор checkpoint по минимальному MSE по latent validation в шагах 1, 250, 500, ...5000. После выбора action model не дообучает визуальный encoder.
- `evaluate_actions.py` использует 1024 сцены, сгенерированные через `web/orbit-core.js` (Node.js), а не напрямую через train_actions simulator. Это отдельный фиксированный протокол.
- Не заявляйте идентичный % на иной реализации без сравнения **одних и тех же сцен**, механики, цели и предиктора.

## Что сохранилось, а что нет

**Есть:** исходники, исходные `.npz` и `resume.pt` (в отдельном архиве), конфиг и `training.json`, история каждого 25-го шага, численные метрики и исходные тестовые прогнозы. Референсный CPU-режим: Linux, Python 3.13.5, PyTorch 2.10.0+cpu, NumPy 2.3.5, 2 CPU потока. Состояние оптимизатора и RNG содержится в отдельном resume checkpoint после 2400 шагов.

**Не записаны в оригинальных метаданных:** точная модель CPU, хост, размер RAM, значения `torch` nondeterminism flags, версия драйвера/микрокода, исходный wall-clock визуальной стадии, точный журнал выбора гиперпараметров до финального опыта. Не реконструируйте эти сведения как исторические факты. В новой среде синтетический эксперимент может отличаться численно.

## Ожидаемые результаты исходного опыта

- Визуальная стадия, 2048 новых траекторий: JEPA+probe ≈ **0.8233 px**, stationary ≈ **3.4117 px**, физический baseline ≈ **0.2596 px**. В контрольной модели без variance/covariance регуляризации ≈ **5.983 px**.
- Action-планировщик, 1024 браузерных сцены: JEPA **694/1024=67.773%**, random 200/1024=19.531%, no-push 243/1024=23.730%, oracle 1024/1024=100%. Тест использует 3 действия из {-1,0,+1}, 27 комбинаций, выбранное действие применяется через импульс 0.035 по оси X в течение 2 ticks с отражением.
- Различие с вашими **69.5%** может быть обусловлено другим набором сцен, seed и протоколом, помимо обучения; этот архив воспроизводит сохранённый **67.773%** benchmark, а не 69.5% из другой оценки.

## Где искать конкретные детали

`configs/original_run.json` — все сохранившиеся параметры; `tinyjepa/core.py` — генератор, энкодер, teacher, loss; `tinyjepa/evaluation.py` — probe; `planning/model.py` — модель действий и симулятор; `train_actions.py` — optimizer и выбор checkpoint; `evaluate_actions.py` — проверка; `reference/` — оригинальные метрики, логи и хеши исходных checkpoint. Новые логи записываются в `logs/`.

Это исходный **упрощённый учебный JEPA-подобный алгоритм**, а не официальный V-JEPA.

Полностью повторены три основных этапа и контрольная модель без регуляризации. На **текущем** виртуальном CPU AMD EPYC 9V74 при двух PyTorch потоках визуальная стадия заняла **17,6 с внутри training loop**, новый action-этап — **10,3 с суммарно**. Это результаты нового воспроизведения, не задокументированное железо первого исторического обучения.
